# Dependency locking

`pyproject.toml` states the constraints. `uv.lock` is the one resolution of
them. Both requirements files are generated from `uv.lock` and are never
hand-edited.

| File | Generated by | Installed by |
|---|---|---|
| `requirements.lock` | `uv export --frozen --no-dev --no-emit-project -o requirements.lock` | `deploy/install.sh` (production) |
| `requirements-dev.lock` | `uv export --frozen --extra dev --no-emit-project -o requirements-dev.lock` | the `backend`, `frontend` and nightly `host-real` CI jobs, and local development |

The `docs` and `frontend` CI jobs export the `docs` extra from `uv.lock` into
temporary constraints, then install MkDocs through those constraints. This pins
the documentation tools and their dependencies without installing application
runtime dependencies in the docs-only job. No separate resolution is maintained.
CI audits this docs selection alongside both committed requirements exports.

## Changing a dependency

1. Edit `pyproject.toml`.
2. `uv lock`
3. Re-run both export commands above, exactly as written — uv records its own
   argument list in each file header, and CI diffs against it.
4. `uv pip install --python .venv/bin/python -r requirements-dev.lock`
5. Run the gates: ruff, ruff format, mypy, `pytest tests/python`, `pytest tests/python/tooling`.

## Why it is gated four ways

Before these gates, `requirements-dev.lock` was produced by `uv pip compile`,
which re-resolves from `pyproject.toml` independently of `uv.lock`. The two
answers drifted: ten packages present in both files — including `sqlalchemy`,
`pydantic`, `fastapi`, `uvicorn` and `libvirt-python` — were pinned differently,
so CI never exercised the dependency set the release ships. The same drift
carried `starlette 1.0.0` and `python-multipart 0.0.27`, seven advisories, into
the `backend` and `frontend` CI jobs and the nightly `host-real` job while
production shipped the fixed versions.

| Gate | Where | Catches |
|---|---|---|
| `uv lock --check` | `dependency-audit` job | `uv.lock` behind `pyproject.toml` |
| regenerate + `git diff --exit-code` | `dependency-audit` job | a lockfile that is not an export of `uv.lock`, including any hand-edit |
| `tests/python/tooling/test_lockfile_consistency.py` | unit job, no uv needed | pins disagreeing with `uv.lock` or with each other |
| `pip-audit --strict` on both files | `dependency-audit` job | known advisories in either set |

uv is pinned — `[tool.uv] required-version` locally, `astral-sh/setup-uv` in CI —
because `uv export` output is not guaranteed byte-stable across uv releases and
the diff gate compares bytes.
