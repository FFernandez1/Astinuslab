# Contributing to AstinusLab

Thank you for your interest in AstinusLab. The project is maintained by one
person, on demand and best effort, without a guaranteed response time.

## Reporting problems

- **Bugs and feature requests:** open an issue using the bug or feature
  template. Include the AstinusLab version or commit, the run mode (development
  checkout or release install), the host (Ubuntu 24.04 LTS, Python 3.12 or 3.13),
  the steps to reproduce, and what you expected.
- **Security vulnerabilities:** never open a public issue. Follow
  [Security reporting and support](docs/community/SECURITY.md).
- **Sensitive data:** never attach memory captures, disk images, credentials,
  admin tokens, SSH keys or personal data. Use synthetic examples and redact
  logs before sharing them.

## Code contributions

For the 1.0.0 release, pull requests from outside contributors are not
accepted. AstinusLab is licensed under the
[Volatility Software License 1.0](LICENSE), and there are no contributor terms
yet; accepting outside code without them would make later licensing changes
harder. To propose a change, open an issue and
describe the problem first. This policy will be revisited after the first
release.
